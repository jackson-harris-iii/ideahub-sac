# Contributing

Start with an issue describing the user need and a small proposed change, or fork the repository and open a pull request. You do not need an invitation to propose code. Jackson reviews merges; direct repository access is not required for a first contribution.

For a PR, explain the problem, resulting behavior, risks and exact checks run. Run `npm run lint`, `npm run typecheck`, `npm test` and `npm run build`. Add behavior tests when changing voting, moderation, consent, authorization or notifications. Use additive migrations and preserve existing idea IDs. Test writes only against a disposable local database.

Never include credentials, live user data, private messages or recordings. Only contribute code and media you have the right to share; code contributions use the repository's MIT license. Third-party marks, submitted ideas and external projects keep their own rights.

Good first contributions: document a clean local install, improve accessibility, verify a dated research link, or move remaining Sacramento examples behind community configuration. Open a project-directory issue to list a project; provide its creator, demo, source, license and maintenance status. A working demo alone does not establish an open-source license.

Be constructive and specific. Discuss code and decisions respectfully; do not publish others' private information. Report safety or security concerns privately using SECURITY.md.
